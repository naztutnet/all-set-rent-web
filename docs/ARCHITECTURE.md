# ALL SET RENT — архитектура магазина и админки

## Решение

Не создаём второй складской backend. Существующий Бот‑Склад остаётся операционным ядром, а Google Sheets — единственным источником правды. Между ним и клиентскими интерфейсами добавляется тонкий HTTP API.

```text
Сайт / Админка / будущая Telegram Mini App
                     ↓
             FastAPI + авторизация
                     ↓
       существующий сервис Warehouse
                     ↓
           Google Sheets + Drive
```

Это сохраняет уже работающие операции, статусы, документы и правила остатков. Новый интерфейс не дублирует данные и не создаёт конфликтующую базу.

## Рекомендуемый стек

- **Сейчас:** текущий лёгкий HTML/CSS/JavaScript фронтенд, чтобы быстро проверить витрину и админские сценарии без миграции ради миграции.
- **При старте Mini App:** React + TypeScript + Vite для общей библиотеки каталога, корзины и форм между сайтом, админкой и Telegram Mini App.
- **UI:** Onest 400/500/600, собственные CSS‑токены, без тяжёлого универсального UI‑набора.
- **API:** FastAPI внутри существующего Python‑проекта Бот‑Склад. Он вызывает текущий сервис `Warehouse`, а не обращается к таблицам вторым независимым способом.
- **Данные:** Google Sheets остаётся источником правды; изображения и оптимизированные WebP/AVIF — в объектном хранилище.
- **Размещение:** API и бот в Docker на существующем VPS; сайт — статический CDN/GitHub Pages на этапе прототипа, затем собственный домен.
- **Платежи:** ЮKassa после юридической настройки магазина. До подтверждения заказа сайт создаёт черновик, а не списывает деньги.

## Минимальный API

### Клиент

- `GET /api/v1/catalog` — опубликованные карточки и цены;
- `GET /api/v1/categories` — категории и порядок вывода;
- `GET /api/v1/availability?from=&to=` — доступность на даты;
- `POST /api/v1/orders/drafts` — создать черновик заявки;
- `PUT /api/v1/orders/{id}/items/{item_id}` — изменить состав;
- `PUT /api/v1/orders/{id}/dates` — изменить период;
- `POST /api/v1/orders/{id}/submit` — отправить на подтверждение.

### Администратор

- `GET /api/v1/admin/catalog` — полная рабочая опись;
- `PATCH /api/v1/admin/catalog/{item_id}` — цена, описание, категория, видимость;
- `POST /api/v1/admin/catalog/{item_id}/photo` — загрузка исходника;
- `GET /api/v1/admin/orders` — очередь заказов;
- `PATCH /api/v1/admin/orders/{id}` — статус и подтверждение.

## Безопасность

- Публичный сайт получает только опубликованные карточки и агрегированный остаток.
- Админские методы закрываются авторизацией и списком разрешённых Telegram ID; публичный `admin.html` сам по себе доступа к данным не даёт.
- Telegram Mini App проверяет `initData` на сервере; клиентские поля не считаются доверенными.
- Все операции изменения используют существующие правила и идемпотентность Бот‑Склада.
- Каталог можно кешировать на 30–60 секунд, доступность — максимум на 10–15 секунд.

## Категории каталога

1. Мебель и рабочие зоны
2. Шатры и защита
3. Свет
4. Климат и обогрев
5. Быт и кейтеринг
6. Офис и печать
7. Связь и медиа
8. Электрика и зарядка
9. Спецэффекты
10. Хозяйство и транспорт
11. Безопасность и экипировка

Названия сформулированы так, чтобы клиент искал оборудование по задаче, а не по внутренней складской классификации.

## Фотостандарт

- Квадрат 960×960, предмет целиком, ракурс 3/4.
- Светлый тёпло‑серый фон, мягкая тень, без декора и текста.
- Реальные пропорции, разъёмы, крепления и маркировка оборудования.
- Один масштаб внутри товарной группы; без случайных ярких цветных подложек.
- Сначала загружается реальная фотография со склада. Генерация может быть временной визуализацией, но не должна выдаваться за фотографию фактического экземпляра.
- В админке отдельно видны готовность данных, готовность фото и статус публикации: весь склад можно внести заранее и выпускать карточки постепенно.

## Последовательность запуска

1. Утвердить категории, карточку товара и фотостандарт на 8–12 ключевых позициях.
2. Добавить FastAPI рядом с Бот‑Складом и подключить read‑only каталог.
3. Подключить авторизацию админки и редактирование карточек.
4. Создание черновика заказа с сайта, проверка доступности и подтверждение менеджером.
5. После стабильной работы — оплата, личный кабинет и Telegram Mini App на том же API.
